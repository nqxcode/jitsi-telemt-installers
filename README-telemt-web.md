# Установщик Telemt WEB Proxy для Jitsi Meet

`telemt-web-install.sh` добавляет прокси типа **WEB** для Telegram к уже работающему Jitsi Meet в Docker. Telegram и Jitsi используют один домен и существующий HTTPS-порт `443`. Nginx направляет запросы к `/jitsi/index/` в отдельный контейнер Telemt. Остальные маршруты обслуживает Jitsi.

На `myawesomejitsi.ru` WEB Proxy уже развёрнут. Для проверки конфигурации на этом сервере начните с `--check`.

Для нового сервера используйте общий установщик [`install.sh`](install.sh). Он сначала настроит Jitsi с HTTPS, затем запустит Telemt.

```bash
sudo bash install.sh --domain meet.example.com --email admin@example.com
```

При совместной установке путь по умолчанию — `/jitsi/index/`. Чтобы задать другой путь из установщика Jitsi, используйте `--telemt-base-path PATH` без начального и завершающего слеша. Этот параметр также включает установку Telemt.

## Требования

- Linux x86_64 и запуск от root.
- Docker с поддержкой `docker network connect --gw-priority`, Docker Compose v2.33.1 или новее и возможность собирать образ через `docker compose up --build`.
- Python 3.11+, Bash, `curl` с поддержкой HTTP/2, `openssl`, `sha256sum`, `tar`, `flock` и системные сертификаты в `/etc/ssl/certs/ca-certificates.crt`.
- Запущенный Compose-сервис Jitsi `web`. Установщик ожидает основной файл `docker-compose.yml`, подключённый в контейнер каталог `/config` и поддержку `nginx-custom/*.conf` в конфигурации Nginx. В rootless-образах Jitsi поддерживается конфигурация `/run/web/config/nginx/nginx.conf`, в более ранних образах используется `/config/nginx/nginx.conf`.
- Домен с одной публичной IPv4-записью. По HTTPS с этим доменом должны открываться Jitsi и `/config.js`. Сертификат должен быть действительным, а публичный HTTPS должен поддерживать HTTP/2. Установщик проверяет адрес с самого сервера.
- При новой установке нужно не менее 100 МиБ свободного места на разделе с каталогом `/root/telemt-web`. Docker дополнительно использует свой каталог данных для слоёв образа и журналов.

Для загрузки релиза нужен доступ с сервера к GitHub. Для работы прокси контейнеру нужен исходящий доступ к дата-центрам Telegram.

## Запуск

Выполните команды на сервере из каталога с установщиком. На `myawesomejitsi.ru` установщик находится в `/root/telemt-web-install.sh`.

1. Проверьте окружение и текущую конфигурацию.

   ```bash
   sudo bash /root/telemt-web-install.sh --domain myawesomejitsi.ru --check
   ```

   При новой установке `--check` проверяет требования и конфликты. Если контейнер, маршрут и сеть уже настроены, он также открывает и закрывает тестовый WEB-сеанс через публичный HTTPS. Конфигурационные файлы и файл ссылки этот режим не записывает.

2. Запустите установку или повторно примените существующие настройки.

   ```bash
   sudo bash /root/telemt-web-install.sh --domain myawesomejitsi.ru
   ```

3. Прочитайте приватную ссылку и откройте её в версии Telegram с поддержкой типа прокси **WEB**.

   ```bash
   sudo cat /root/telemt-web/web-proxy-link.txt
   ```

   Ссылка начинается с `tg://webproxy?` и содержит секрет доступа. Файл создаётся с правами `0600`. При первом применении установщика к уже развёрнутой конфигурации файл ссылки появится после запуска без `--check`.

## Параметры

| Параметр | Что задаёт |
| --- | --- |
| `--domain DOMAIN` | Обязательное полное имя домена Jitsi в нижнем регистре. |
| `--public-ip IPV4` | Публичный IPv4 прокси. Значение должно совпасть с единственной IPv4-записью домена. По умолчанию установщик берёт адрес из DNS. |
| `--base-path PATH` | Путь прокси. По умолчанию `jitsi/index`. Указывайте без начального и завершающего слеша. Выбирайте путь, свободный в конфигурации Jitsi. |
| `--jitsi-container NAME` | Имя контейнера Compose-сервиса `web`. При единственном запущенном контейнере с образом `jitsi/web` установщик определяет имя сам. |
| `--subnet CIDR` | Приватная подсеть Docker размера `/29`. По умолчанию `172.30.85.0/29`. Выбирайте свободную подсеть, если эта уже используется. |
| `--check` | Проверка без изменения конфигурации. |
| `--help` | Справка по запуску. |

При повторном запуске используйте те же параметры. Для установки, где ещё используется прежний путь `telegram/web`, передайте `--base-path telegram/web`. Если существующий файл отличается от конфигурации, которую должен создать установщик, скрипт укажет путь к файлу и остановится. Смена пути работающего веб-прокси требует согласованных изменений в Nginx и Telemt и новой ссылки для Telegram.

## Как устроен прокси

```text
Telegram
  | HTTPS :443   /jitsi/index/
  v
Nginx в контейнере Jitsi (172.30.85.2)
  | HTTP/1.1 через сеть telemt-web-ingress
  v
Telemt (172.30.85.3:18080)
  | MTProto
  v
Дата-центры Telegram
```

Адреса в схеме соответствуют подсети по умолчанию. При выборе другой подсети установщик берёт адреса с теми же смещениями. Существующий MTProxy на порту `8898` на `myawesomejitsi.ru` работает в своём контейнере.

### Контейнер Telemt

Установщик загружает официальный бинарный релиз **Telemt 3.5.17** для Linux x86_64 (musl). Перед сборкой сверяет SHA-256 архива и извлечённого бинарника. Бинарник запускается в минимальном Docker-образе с файловой системой только для чтения, временным каталогом состояния и политикой перезапуска `unless-stopped`.

Telemt использует транспорт `https` для WEB-прокси. Внутренний слушатель `18080` подключён к приватной сети Docker. Управляющий API отключён. Установщик создаёт отдельный секрет пользователя `web-user`; при повторном запуске берёт его из существующего `telemt.toml`.

### Docker Compose и Nginx Jitsi

Установщик создаёт рядом с основным файлом Compose Jitsi файл `docker-compose.override.yml`. Он добавляет сервису `web` сеть `telemt-web-ingress` и закрепляет адрес `172.30.85.2`. Значение `external: true` указывает Compose использовать сеть, уже созданную установщиком. Приоритет шлюза `-1` сохраняет обычный выход Jitsi через его основную сеть. Скрипт подключает сеть к уже запущенному контейнеру, а override сохраняет это подключение при последующем пересоздании через стандартный Compose-проект. Если вы вручную перечисляете файлы через `docker compose -f`, включайте также файл override.

В каталоге Jitsi, смонтированном в контейнер как `/config`, установщик добавляет `nginx-custom/telemt-web.conf`. В rootless-образах он также копирует файл в рабочий каталог `/run/web/config/nginx-custom/` текущего контейнера. При новом старте Jitsi сам читает сохранённый файл из `/config`. Правило передаёт весь путь и параметры запроса в Telemt, подставляет реальный IP клиента в `X-Forwarded-For` и отключает буферизацию для долгих запросов. Nginx использует существующий сертификат Jitsi. Журнал доступа для маршрута отключён, так как параметры WEB-запросов могут содержать данные авторизации.

После `nginx -t` установщик плавно перечитывает конфигурацию через `nginx -s reload`. Затем он проверяет `/config.js`, обработку запросов без авторизации и полный цикл открытия и закрытия авторизованного WEB-сеанса. Проверка сеанса не заменяет проверку подключения из приложения Telegram.

## Где находятся файлы

| Файл | Назначение |
| --- | --- |
| `/root/telemt-web-install.sh` | Установщик на `myawesomejitsi.ru`. |
| `/root/telemt-web/compose.yaml` | Описание контейнера WEB Proxy. |
| `/root/telemt-web/telemt.toml` | Настройки Telemt и секрет пользователя. |
| `/root/telemt-web/web-proxy-link.txt` | Приватная ссылка для импорта в Telegram. |
| `/root/telemt-web/public/` | Статическая страница, которую Telemt отдаёт для обычных запросов. |
| `docker-compose.override.yml` в каталоге Compose Jitsi | Постоянное подключение Jitsi к сети WEB Proxy. |
| `nginx-custom/telemt-web.conf` в каталоге конфигурации Jitsi | Маршрут HTTPS до Telemt. |

На `myawesomejitsi.ru` каталог Compose Jitsi находится в `/root/jitsi-docker-jitsi-meet-2b459c5`, а конфигурация контейнера `web` — в `/root/.jitsi-meet-cfg/web`.

## Проверка и устранение ошибок

| Симптом | Что проверить |
| --- | --- |
| `--check` сообщает об ошибке DNS или HTTPS | Проверьте, что домен имеет единственную A-запись, она совпадает с `--public-ip`, а `https://ДОМЕН/config.js` доступен с сервера по HTTP/2 без редиректа. |
| Установщик находит несовместимый файл | Изучите названный файл. Установщик сохраняет сторонние изменения и останавливается. Если такой файл уже содержит вашу настройку, сопоставьте её со схемой выше перед ручным объединением конфигураций. |
| Docker сообщает о пересечении подсетей при первой установке | Выберите другую свободную приватную сеть `/29` через `--subnet`. Если неудачный запуск уже создал `/root/telemt-web`, а контейнер ещё не был развёрнут, перенесите этот каталог в резервную копию перед повторной попыткой с новой подсетью. |
| Браузер получает `404` на `/jitsi/index/` | Для обычного запроса без данных авторизации это ожидаемо. Используйте `--check` для проверки авторизованного сеанса. |
| Возникает `502` или WEB-сеанс не открывается | Проверьте состояние контейнера `telemt-web`, его адрес в сети `telemt-web-ingress` и правила маршрута в Nginx. |
| Подключение в Telegram не работает при успешном `--check` | Проверьте, что клиент поддерживает тип **WEB** и импортирована полная ссылка из файла. |

На `myawesomejitsi.ru` состояние контейнера, сеть и синтаксис Nginx можно посмотреть так:

```bash
sudo docker ps -a --filter 'name=^/telemt-web$'
sudo docker network inspect telemt-web-ingress
sudo docker exec jitsi-docker-jitsi-meet-2b459c5-web-1 nginx -t -c /config/nginx/nginx.conf
```

Стартовый журнал Telemt может содержать приватную ссылку. Скрывайте её перед публикацией журнала.

При ошибке установки скрипт убирает маршрут, Compose-override, сетевое подключение Jitsi, контейнер и сеть, если их создал именно этот запуск. Локальные файлы Telemt и секрет сохраняются в `/root/telemt-web` для повторной попытки.
