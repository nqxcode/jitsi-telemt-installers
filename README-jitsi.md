# Установщик Jitsi Meet в Docker

`jitsi-install.sh` разворачивает **Jitsi Meet stable-11509-1** на Linux. Скрипт настраивает HTTPS, создаёт аккаунт организатора и проверяет, что Jicofo видит рабочий медиамост. По желанию он также запускает соседний установщик Telemt и добавляет Telegram WEB Proxy по пути `/jitsi/index/` на том же домене.

На `myawesomejitsi.ru` скрипт лежит в `/root/jitsi-install.sh`. Действующий Jitsi на этом сервере был развёрнут отдельно и уже использует нужные порты. Этот установщик предназначен для новой установки и последующих запусков своего Compose-проекта.

## Требования

- Linux, доступ root, работающий локальный Docker и плагин Docker Compose.
- Bash, Python 3.11 или новее, `curl` с HTTP/2, `openssl`, `tar`, `sha256sum`, `ss` и `flock`.
- Публичное доменное имя в нижнем регистре с одной DNS-записью A. Если задан `--public-ip`, он должен совпадать с этой записью.
- Входящий **TCP 443** для HTTPS и **UDP 10000** для медиамоста. Для выпуска и продления сертификата через встроенный Let's Encrypt требуется публично доступный **TCP 80**.
- Свободные локальные порты TCP 8080 и 8888 для диагностики JVB и Jicofo. Compose публикует их на `127.0.0.1`.
- Исходящий доступ к GitHub для загрузки архива, к GHCR для загрузки образов и к Let's Encrypt при автоматическом выпуске сертификата.

Установщик проверяет занятость портов на сервере. Правила облачного файрвола и переадресацию портов при необходимости настройте до запуска. Если у домена есть запись AAAA, она должна вести на доступный по IPv6 адрес того же сервиса. Для совместной установки с Telemt нужны x86_64, Docker Compose 2.33.1 или новее и команда `docker network connect --gw-priority`.

## Быстрый старт

Для нового сервера замените домен и email в примерах своими значениями. Email используется для регистрации в Let's Encrypt.

1. Проверьте окружение.

   ```bash
   sudo bash jitsi-install.sh --domain meet.example.com --email admin@example.com --check
   ```

2. Запустите установку.

   ```bash
   sudo bash jitsi-install.sh --domain meet.example.com --email admin@example.com
   ```

3. Прочитайте логин и пароль организатора.

   ```bash
   sudo cat /opt/jitsi-meet/organizer.env
   ```

   Откройте `https://meet.example.com/`, создайте комнату и войдите как организатор. После входа гости смогут присоединиться по ссылке. Файл с учётными данными создаётся с правами `0600`.

### Свой сертификат

Для ручной настройки HTTPS передайте полный PEM-сертификат с цепочкой и соответствующий приватный ключ без пароля.

```bash
sudo bash jitsi-install.sh --domain meet.example.com \
  --tls-cert /path/to/fullchain.pem --tls-key /path/to/privkey.pem
```

Установщик проверяет имя, срок действия и соответствие ключа. HTTPS-проверка также требует, чтобы система доверяла цепочке. В этом режиме выпуск и продление сертификата выполняет владелец сервера. При повторном запуске установщик сверяет переданные файлы с установленными, поэтому подмена сертификата входными аргументами не выполняет ротацию.

### Jitsi и Telemt вместе

Для нового сервера используйте общий установщик [`install.sh`](install.sh).

```bash
sudo bash install.sh --domain meet.example.com --email admin@example.com
```

Jitsi сначала проверит HTTPS, медиамост и аккаунт организатора. Затем установщик Telemt добавит приватный слушатель, подключит его к Nginx Jitsi и проверит авторизованный WEB-сеанс. По умолчанию публичный маршрут — `https://meet.example.com/jitsi/index/`, а ссылка для Telegram сохраняется в `/root/telemt-web/web-proxy-link.txt`.

Для другого пути используйте, например, `--telemt-base-path jitsi/proxy`. Этот параметр включает установку Telemt. Подробности о сети Docker, маршруте Nginx и проверке ссылки есть в [README Telemt](README-telemt-web.md).

## Параметры

| Параметр | Назначение |
| --- | --- |
| `--domain DOMAIN` | Обязательный домен Jitsi. |
| `--public-ip IPV4` | Публичный IPv4 медиамоста. По умолчанию берётся из DNS. |
| `--email ADDRESS` | Email для автоматического выпуска сертификата Let's Encrypt. |
| `--tls-cert FILE`, `--tls-key FILE` | Собственный сертификат и ключ. Используются вместо `--email`. |
| `--organizer NAME` | Логин организатора. По умолчанию `organizer`. Разрешены строчные латинские буквы, цифры и подчёркивания. Первый символ должен быть буквой. |
| `--with-telemt` | Запускает установщик Telemt после проверки Jitsi. |
| `--telemt-base-path PATH` | Задаёт путь WEB Proxy и включает Telemt. По умолчанию `jitsi/index`. Укажите путь без начального и завершающего слеша. |
| `--telemt-installer FILE` | Указывает другой путь к скрипту Telemt и включает Telemt. |
| `--check` | Режим проверки. На новом сервере проверяет окружение. Для развёрнутого этим скриптом проекта также проверяет HTTPS, Nginx, медиамост и наличие аккаунта организатора. |
| `--help` | Печатает справку. |

## Что создаёт скрипт

Скрипт сверяет SHA-256 архива официального релиза, извлекает `docker-compose.yml` и запускает контейнеры `web`, `prosody`, `jicofo` и `jvb`. Настройки хранятся в каталоге `/opt/jitsi-meet`.

| Путь | Назначение |
| --- | --- |
| `/opt/jitsi-meet/docker-compose.yml` | Compose-файл релиза Jitsi. |
| `/opt/jitsi-meet/.env` | Домен, порты, настройки TLS, учётные данные внутренних компонентов. |
| `/opt/jitsi-meet/organizer.env` | Логин и пароль организатора. |
| `/opt/jitsi-meet/config/` | Конфигурация контейнеров и постоянные данные, включая данные Prosody и сертификаты. |
| `/opt/jitsi-meet/docker-compose.override.yml` | Дополнительное сетевое подключение Jitsi. Появляется при настройке Telemt. |

Повторный запуск с теми же параметрами использует сохранённые настройки и учётные данные. Compose запускается с `--no-recreate`, поэтому работающие контейнеры сохраняются. Если проверка запуска не проходит, установщик оставляет каталог и контейнеры для диагностики и повторного запуска. Если после запуска Jitsi не проходит установка Telemt, Jitsi остаётся развёрнутым.

## Диагностика

Проверку уже развёрнутого проекта запускайте с теми же параметрами TLS, домена и организатора, что и при установке. Для совместной проверки добавьте `--with-telemt` и тот же `--telemt-base-path`, если он был задан. Наличие аккаунта в Prosody проверяется отдельно от входа через браузер.

Состояние контейнеров и последние записи журналов можно посмотреть из каталога проекта.

```bash
cd /opt/jitsi-meet
sudo docker compose -p jitsi-meet ps
sudo docker compose -p jitsi-meet logs --tail 100 web jicofo jvb
```

| Симптом | Что проверить |
| --- | --- |
| Установщик сообщает, что порты заняты | Посмотрите, какие процессы или контейнеры используют 80, 443, 8080, 8888 или UDP 10000. На сервере с действующим Jitsi диагностируйте его текущий Compose-проект. |
| Let's Encrypt не выпускает сертификат | Проверьте DNS, публичный доступ к TCP 80 и журнал `web`. |
| Страница открывается, но нет аудио или видео | Проверьте внешний доступ к UDP 10000, правильность публичного адреса медиамоста и журналы `jicofo` и `jvb`. Успешная проверка HTTPS не проверяет прохождение медиатрафика через внешний файрвол. |
| Jitsi работает, а WEB Proxy не открывается | Запустите проверку отдельно через `telemt-web-install.sh --domain ДОМЕН --check`. Для нестандартного пути передайте `--base-path` с тем же значением. |
